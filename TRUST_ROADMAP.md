# Wine Memory trust roadmap

## Goal

Make every recommendation understandable: what came from the user, what came
from a verified source, what is a general pairing principle, and what was
generated by AI.

## Recommendation architecture

1. **Personal facts:** the user's ratings, notes, budget, cellar, and stated tastes.
2. **Verified wine facts:** producer, cuvée, vintage, region, grapes, critic/source,
   rating, review date, and a link to the source.
3. **Pairing rules:** a maintained set of food-and-wine principles with an explicit
   rule name and confidence.
4. **AI explanation:** use AI to explain and compare the evidence, never to invent
   a bottle identity, rating, price, availability, or critic endorsement.

## Release sequence

### Release 1 — Honest recommendations

- Add source and confidence labels to every suggestion.
- Require confirmation of scanned/search-identified wines.
- Hide unsupported ratings, prices, and availability.
- Show why a bottle matches the meal and the user's history.

### Release 2 — Reliable wine records

- Add a canonical wine identity and duplicate detection.
- Track verified versus user-entered versus AI-inferred fields.
- Add correction history so confirmed facts are not silently overwritten.

### Release 3 — Trusted outside recommendations

- Integrate selected sources only with permission/licensing appropriate to each
  source.
- Store critic/source, score, publication date, retrieval date, and direct link.
- Rank recommendations from evidence, then let AI explain the ranking.

### Release 4 — Shopping help

- Add budget and store/location preferences.
- Verify current price and availability at request time.
- Clearly distinguish “good stylistic fit” from “available to buy now.”

## Current release gate

Do not deploy to production until ownership, backup, private photo storage, and
preview testing are complete.
